# CLAUDE.md — TrendLib

TrendLib is an open-source technical-analysis indicator library: a Rust core,
published to PyPI as `trendlib` (`pip install trendlib`, `import trendlib as tl`)
and later to crates.io as `trendlib`. It is built by GAIIN Technologies.

You are building it milestone by milestone. The docs below are the spec. They win
over your own preferences; if two docs disagree, or a doc is wrong, stop and ask.

## Hard rules

1. **One folder per indicator is the source of truth:**
   `crates/trendlib/src/indicators/<name>/` holds `spec.yaml` (metadata, never
   logic), `mod.rs` (algorithm, never metadata), `doc.md`, and `golden/*.csv`.
2. **Never hand-edit a GENERATED file.** Change the inputs, run
   `cargo xtask generate`. Generated files start with a
   `@generated by cargo xtask generate — do not edit` banner; generated sections
   inside hand-written files sit between `@generated begin` / `@generated end`
   markers.
3. **Golden values are produced by running an independent oracle** (see
   `docs/TESTING.md`). Never compute expected values with TrendLib's own formula
   or a re-derivation of it and label them as an oracle. If no oracle can be run,
   stop and say so.
4. **Never invent a parameter name, default or range.** They come from
   `docs/INDICATORS.md` or an approved spec issue. Missing → ask.
5. **Never loosen a tolerance or edit a shared test to make something pass.**
   Ask first.
6. **Stream output equals batch output bitwise**, bar for bar, for every
   indicator. Path dependence is not an excuse; see `docs/CONVENTIONS.md`.
7. **Outputs are measurements, not advice.** No function, output, parameter or
   doc may be named or worded as a trade instruction: buy, sell, entry, exit,
   target, recommendation, or "signal" in the sense of "act now". Established
   indicator terms are fine (MACD's signal line is `macd_signal`). GAIIN operates
   under Indian securities regulation; the library describes, it does not advise.
8. **No global mutable state** anywhere: no settings singletons, no caches shared
   across calls. Every stream is an independent value.
9. The core crate is `#![forbid(unsafe_code)]` and has **zero runtime
   dependencies**. The bindings crate may use PyO3 and `numpy`; `xtask` may use
   whatever it needs.

## Working style

- Do only the current milestone. Stop at its end and report (format below).
- Before writing code for a milestone, list anything in the docs that is
  ambiguous, contradictory or that you believe is wrong, with a proposed
  resolution. Wait for answers only if a wrong guess would be expensive to undo;
  otherwise state the assumption, record it in `docs/DECISIONS.md` under
  "Assumptions pending review", and continue.
- Work on a branch named `m<N>-<slug>`. Small commits, imperative subject lines.
  Never push, tag, publish or open a release without explicit approval.
- When a doc turns out wrong, fix the doc in the same commit as the code and say
  so in your report. Do not let code and docs drift.

## Before you say a task is done

Run all of these and quote the result lines in your report:

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo xtask regen-check        # from M2 on
maturin develop --release && pytest -q
```

## Code comments

Default to none. Comment only a non-obvious *why*, or a pitfall that fails
silently. Never narrate what the next lines do, history, or rejected
alternatives — those go in commit messages.
